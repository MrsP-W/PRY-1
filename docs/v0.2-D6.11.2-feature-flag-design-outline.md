# D6.11.2 Feature Flag 设计大纲 — design-only(2026-07-28)

> **范围声明(优先于正文)**:本文为 D6.11.2 设计大纲,**仅章节标题 + 关键决策点**,**不改 `src/` 任何文件**,**不接运行时**。落地执行需 P3 观察期通过 + 用户单独授权后逐项推进。

---

## 1. 目标(Why)

### 1.1 现有痛点(不修会出事的)

- **ENABLE_* 环境变量**:`ENABLE_PATH_4_WRITE=1` / `ENABLE_NOTES_ENCRYPTION=1` / `ENABLE_SMTP_REAL_NETWORK=1` 走环境变量,缺审批链 / 缺审计 / 缺回滚 trail
- **撞坑 #1/#18/#65/#71/#76/#78/#79/#81/#85/#86/#87/#88/#92/#93/#94/#97/#98 红线**:`ENABLE_*` 一旦开启难即时撤回,无分级保护
- **P3 观察期 demand**:`collecting` / `attention` 状态需有"feature gate"在观察期拦截非预期路径

### 1.2 目标 3 句话

1. **分级启停** — 替代平铺式 `ENABLE_*`,按敏感度分 L0/L1/L2 三级
2. **可审计** — 每次 flag 状态变更留 trail(actor / timestamp / reason / 回滚路径)
3. **可回滚** — 任意 flag 1 个 API 调用回到 OFF,带自动 alerting

---

## 2. 接口契约(关键决策点)

### 2.1 Flag 名称规范

| 维度 | 范本 | 备注 |
|------|------|------|
| 全名 | `<scope>.<feature>.<behavior>` | 例:`email.smtp.real_network` |
| 域(scope) | email / notes / sap / menu_bar / agent_run | 与现有 L1 适配器对齐 |
| 粒度 | 单 feature 一个 flag | 不打包(便于审批) |

### 2.2 类型与默认值

| 类型 | 范本 | 默认 |
|------|------|------|
| `BoolFlag` | 开关型(替代 `ENABLE_*`) | OFF |
| `PercentFlag` | 灰度型(0-100,逐步放量) | 0 |
| `TierFlag` | 分级型(L0/L1/L2 用户组可见) | L0(最严) |

### 2.3 作用域

- **运行时**:进程内 `FlagRegistry`(只读 + 缓存)
- **持久化**:`~/Library/Application Support/MyAIEmployee/feature_flags.json`(只 audit 变更 trail)
- **跨进程**:通过 SQLCipher `flags` 表(待 L4 落地)

### 2.4 过期策略

- **TTL**:每个 flag 强制设 `expires_at`(最长 90 天)
- **过期自动 OFF**:`expires_at < now()` → 自动回滚 OFF + audit log
- **续期需重新审批**

## 3. 状态机(关键决策点)

```
[OFF] ──审批通过──> [ROLLOUT_PERCENT] ──全量──> [ON]
   ↑                      │                    │
   └──── 回滚 ────────────┴────── 回滚 ─────────┘
                                                 │
                                          TTL 到期 → [EXPIRED]
                                                 │
                                          弃用 → [DEPRECATED]
```

### 3.1 5 状态

| 状态 | 含义 | 转换触发 |
|------|------|---------|
| `OFF` | 完全关闭 | 默认 / 回滚 / 到期 |
| `ROLLOUT_PERCENT` | 灰度中(0-100%) | 审批通过 + 选 PercentFlag 类型 |
| `ON` | 全量开启 | 灰度 100% 或审批直接全量 |
| `EXPIRED` | TTL 到期 | 自动转 OFF + audit |
| `DEPRECATED` | 永久关闭 | 标记 + audit(代码移除后) |

### 3.2 转换矩阵

| from | to | 触发条件 | 审批级别 |
|------|----|---------|---------|
| OFF | ROLLOUT_PERCENT | 提交"灰度申请" | L1 |
| OFF | ON | 提交"全量申请" | L2 |
| ROLLOUT_PERCENT | ON | 灰度进度 100% | L1 |
| ROLLOUT_PERCENT | OFF | 任何时候(回滚) | L0(立即) |
| ON | OFF | 任何时候(回滚) | L0(立即) |
| 任意 | EXPIRED | TTL 到期 | 自动(无审批) |
| 任意 | DEPRECATED | 标记弃用 | L0 |

---

## 4. 审批链(关键决策点)

### 4.1 三级审批

| 级别 | 谁来批 | 适用 flag 类型 | SLA |
|------|--------|---------------|-----|
| **L0** | 用户本人(命令行 / dashboard 一键) | 所有 flag 紧急回滚 | < 5s |
| **L1** | 用户本人 + 工具(申报理由 + 自动审) | ROLLOUT 灰度 / 常规 ON | < 1h |
| **L2** | 用户本人 + @审计员 + 评审会 | 涉及数据外发 / 财务 / SAP 真写 | < 24h |

### 4.2 审批信息 4 必填

1. **actor**(谁)
2. **reason**(为何开)
3. **rollback_plan**(回滚路径)
4. **expires_at**(何时自动关)

### 4.3 与现有 enable 命令的关系

| 现有 | 替代为 | 区别 |
|------|--------|------|
| `ENABLE_SMTP_REAL_NETWORK=1` | `feature_flag.email.smtp.real_network: ON` | 加审批 + trail + TTL |
| `ENABLE_PATH_4_WRITE=1` | `feature_flag.notes.path4.write: ON` | 同上 |
| `ENABLE_NOTES_ENCRYPTION=1` | `feature_flag.notes.encryption.v3: ON` | 同上 |

> **迁移策略**:双轨运行 90 天,旧 `ENABLE_*` 仍可读但新代码路径走 Feature Flag;90 天后旧路径标记 DEPRECATED。

## 5. 回滚路径(关键决策点)

### 5.1 立即回滚(L0)

- **接口**:`flag.set(flag_name, state="OFF", actor=user, reason="emergency")`
- **SLA**:< 5s 生效(进程内热更新 + 持久化)
- **触发**:dashboard 红色按钮 / CLI `flag-rollback <name>` / 自动(健康度异常)
- **审计**:写入 `flags_audit` 表(actor/timestamp/from_state/to_state/reason)

### 5.2 渐进回滚(灰度场景)

- ROLLOUT_PERCENT 100% → 50% → 0%(每步独立审计)
- 自动监控:`attention != []` 持续 3 个 epoch → 自动回滚 + alerting

### 5.3 回滚失败兜底

- 进程内 registry 已回 OFF,但某运行中 subprocess 仍持有旧值 → subprocess 隔离 + 单进程重启
- **禁止**:回滚不生效但继续执行(必须 subprocess 显式重读 flag)

## 6. 与 P3 观察期的对接

| P3 状态 | Feature Flag 行为 |
|---------|------------------|
| `collecting` | 仅 OFF / 灰度 0-10% 允许,其余拒绝 |
| `attention=[]` 连续 7d | 可灰度到 50% |
| `attention=[]` 连续 30d | 可全量 ON |
| `fail_attention` 出现 | 自动回滚所有 ROLLOUT/ON 状态 flag |

---

## 7. 与反馈评测的集成

- 每个 flag ON 启用时,**强制关联 1 个评测集**(如 email_draft 003 + 004)
- 评测集失败率 > 5% → 自动回滚 + alerting
- 与 D6.10.1/10.2 评测样本 4→15→30 同步增长

## 9. 红线(写进 flag_audit 表)

- ❌ **默认禁止 ON** — 所有 flag 默认 OFF,启停必须走审批链
- ❌ **不抢控制权** — flag 状态变更必须用户主动操作(无 AI 自动开)
- ❌ **不联网外传** — flag 状态变更 trail **不** 走云端(本地 + Keychain 可选)
- ❌ **P3 观察期不启用高敏感 flag** — SMTP / Notes 真写 / SAP 真写 / 财务 默认锁
- ❌ **不替代撞坑保护** — 撞坑 #1/#18/#65/#71/#76/#78/#79/#81/#85/#86/#87/#88/#92/#93/#94/#97/#98 红线保留,Feature Flag 是**叠加层**而非**替代层**
